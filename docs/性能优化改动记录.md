## 二、 iOS Safari 防卡顿与防闪退补丁清单（补在官方架构之上，零 UI 破坏）

### 0. 聊天记录会话排序缓存、主题 DB 单连接与渲染元数据预计算（防高频分配 OOM 闪退）
- `lib/chat-storage.ts`：① 在 `messagePositionsBySession` 之上必须维护 `_sortedSessionCache`（避免每次 `loadChatMessages` 都 `.map().sort()` 新建几千条数组导致内存爆表），并在 `pushChatMessage` / `editChatMessage` / `retractChatMessage` / `updateMessageMedia*` 中做不可变增量更新；② `resolvePendingAvatarRecommendation` 只倒序扫当前会话末尾 48 条，禁止 `[..._messagesCache].reverse()`；③ `getLatestCharacterStateValues` 走各会话 `getSortedSessionMessages` 尾部倒序查找，禁止全表过滤排序。
- `lib/chat-avatar-intent.ts`：`findUserAvatarChangeIntent` 先截取 `history.slice(-48)`。
- `lib/theme-storage.ts`：`openThemeDb` 复用单例 `_themeDbPromise`；`getThemeAssetMap` / `readThemeAssetRecords` 走 `readAssetRecordsBatch` 单事务批量读；所有事务必须先挂 `const done = runTransactionDone(transaction)` 再发请求，严禁 `await runRequest` 后再挂 `oncomplete`。
- `components/chat/chat-room.tsx`：必须保留 `projectedMessageRenderMeta`（`useMemo`），預先一次算出 `displayContents`、`hiddenFlags`、`prevVisibleMessages`，严禁在气泡渲染 `map` 循环内回扫历史重复调 `getMessageDisplayContent`。
- `components/map/map-app.tsx`：挂载时调用 `hydrateThemeBlobs()`。

> 说明：官方已在 PR #33（`docs/chat-memory-window-fixes.md`）内置了聊天消息按会话位置索引、短期记忆窗口化与分批让出主线程。以下 **18 个文件微调** 是专门针对 iOS WebKit 内存红线与后台冻结机制的补充：

### A. 点击生成 0s~1s 防卡死（高频 `kvGet` 字符串引用缓存与短期记忆有界扫描）
1. `lib/character-world-storage.ts` & `lib/settings-storage.ts`（`loadCharacterWorldGroups` / `loadUserIdentities`）：
   - `settings-storage.ts` 的 `loadUserIdentities` 必须按 `_userIdentitiesMemoRaw` 缓存解析结果（否则每次返回新数组引用会导致 `loadCharacterWorldGroups` 的引用比对 100% 失效）；
   - `character-world-storage.ts` 按 `raw === _worldGroupsMemoRaw && characters === _worldGroupsMemoCharsRef && identities === _worldGroupsMemoIdentitiesRef` 缓存世界分组，消除组装短期记忆时 6000 次重复 `JSON.parse`。
1b. `lib/short-term-assembler.ts` & `lib/chat-engine.ts`（`assembleNativeTimeline` / `prepareShortTermContext`）：
   - 传入 `allowedSources` 提前跳过已关闭的记忆来源，避免无意义读取与格式化；
   - 传入 `maxMessagesPerSession`（按预算限制单会话最多扫描末尾 400~1500 条，朋友圈最多 100 条），且合并 `history` 池时从最新消息往前倒序累加 Token、达到预算上限立即停止，避免全表扫描 3 万条远古消息。
2. `lib/calendar-storage.ts`（`loadStore` / `saveStore`）：
   - 按 `_calendarStoreMemoRaw` 缓存日历计划解析结果。
3. `lib/diary-entry-storage.ts`（`loadDiaryEntries` / `saveDiaryEntries`）：
   - 按 `_diaryEntriesMemoRaw` 缓存手记列表解析结果。
4. `lib/custom-app-storage.ts`（`loadInstalledCustomApps` / `saveInstalledCustomApps`）：
   - 按 `_installedCustomAppsMemoRaw` 缓存已安装自定义 APP 列表。
5. `lib/mixology/storage.ts`（`readJson` / `writeJson`）：
   - 用 `_mixJsonMemo` Map 按 key 缓存 `{ raw, value }`，消除进特调对局时 22 次重复解析 14MB 对局库。
6. `lib/api-log-store.ts`：
   - `MAX_API_LOGS = 40`、`MAX_QA_API_LOGS = 30`、`MAX_API_LOGS_SERIALIZED_CHARS = 1.5MB`，防止每次请求后序列化 8MB 日志卡死主线程。

### B. 聊天室双开防闪退、切后台防时间戳漂移与表情包按需加载
7. `components/chat/chat-room.tsx`（仅改 3 处局部逻辑，严禁动 DOM 结构与生命周期）：
   - **进房按需预热表情包**：`usedStickerNames` 只提取当前可见 `msgs`（30 条）里的 `sticker` 名称传给 `prewarmStickerCache(id, usedStickerNames)`；
   - **双聊天室同时生成防闪退**：所有 6 处 `onStreamDelta` / `onOfflineDelta` 在 `streamAccumRef.current += delta` 后加 `if (!isChatRoomElementVisible(wrapperRef.current)) return;`，隐藏聊天室不触发 `setStreamPreview` 整树重渲染；
   - **切后台跳过 800ms 延迟立即落库**：`splitAndSaveAIMessages` 中若 `document.visibilityState === "hidden"` 或 `!isChatRoomElementVisible(wrapperRef.current)`，不等待 `abortableDelay(800)` 直接调用 `publishVisibleMessage` 落库，防止定时器在后台被 iOS 冻结导致十几分钟后切回前台时时间戳变成当前时间并引发重启。
8. `components/chat/message-bubble.tsx`：
   - `prewarmStickerCache(characterId, onlyNames?: Set<string>)` 支持只按需解析传入的贴纸名集合；`StickerBubble` 的 `<img>` 加 `loading="lazy" decoding="async"`。
9. `components/chat/emoji-panel.tsx`：
   - `StickerPanel` 增加 `STICKER_PAGE_BATCH = 35` 分批渲染与「加载更多」按钮，且只解析当前激活图集 `activePack`，不一次性解码所有图集。
10. `components/chat/sticker-search-suggest.tsx`：

11. `components/chat/chat-settings-panel.tsx`：
    - 用 `memo(...)` 包裹 `ChatSettingsPanel`（比较 `prev.session === next.session && prev.offlineHistoryBusy === next.offlineHistoryBusy`），隔离流式生成期间的重渲染。

12. `lib/bg-timer.ts`：
    - 维护 `intervalIds` 集合，当 `document.visibilityState === "hidden"` 时跳过 `bgSetInterval` 的周期性 tick 回调，防止切去刷其他 App 时后台唤醒跑重任务被 iOS OOM 强杀。

14b. `lib/push-outbox-client.ts` & `lib/follow-up-service.ts`（离线预约与定时联系时间戳保真）：
